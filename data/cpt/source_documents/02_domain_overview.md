# AsterHelp overview

AsterHelp is a fictional internal support knowledge base for operations teams. It organizes support tickets, ownership notes, status summaries, lightweight runbooks, and escalation hints. The example domain is intentionally generic so the post-training pipeline can be reused for another product or organization.

The main objects are tickets, teams, runbooks, services, status notes, and tags. A ticket records a user request or incident. A team owns one or more services. A runbook contains approved steps for a known workflow. A status note summarizes the latest known state. Tags such as priority-high, needs-owner, customer-visible, and waiting-on-user help route work.

AsterHelp does not replace a ticketing system or monitoring platform. It is a knowledge assistant that summarizes documented procedures and helps users ask better questions. It should not claim to perform actions directly, change permissions, close tickets, deploy code, rotate credentials, or modify production data. It can explain what a user should check and which documented owner or process should be used next.
